# 졸음운전 감지 (geumjjogi-drowsy)

졸음운전 경고: 웹캠 영상에서 눈 감김·하품·고개 숙임을 실시간으로 분석해 졸음을 감지하고 경고한다.

---

## <img src="assets/geumjjogi_logo.png" width="36" alt="GEUMJJOGI 로고" align="absmiddle"> 팀원(금쪽이 - GEUMJJOGI)

| 역할 | 이름 | 담당 |
| --- | --- | --- |
| 팀장 | 장범수 | 데이터 수집, 특징 추출, 라벨링, 학습 데이터 생성 |
| 팀원 | 김민영 | LSTM, 눈 감김 판정, 평가 |
| 팀원 | 육주영 | 1D-CNN, 하품·고개 숙임 판정, 데모 |

주요 작업은 최종 기획서 7-1을 본다.

기간: 2026.10.26 ~ 11.09 (발표 11.09). 자세한 계획은 최종 기획서(2026-11-03)를 본다.

## 📌 프로젝트 소개

1. MediaPipe Face Landmarker로 얼굴 좌표 17개(눈 12, 입 4, 코끝 1)를 뽑고, 프레임마다 특징 11개(`face, ear_l, ear_r, ear, mar, pitch, yaw, roll, blink_l, blink_r, jaw_open`)를 계산한다.
2. **졸음 단계**는 연속 눈 감김 시간으로 정한다. 규칙과 모델이 같은 타이머(`rule_based/alarm.py`의 `ClosureTimer`)를 쓴다.

    | 단계 | 연속 눈 감김 | 화면 |
    | --- | --- | --- |
    | 정상 | 1.5초 미만(깜빡임 포함) | 표시 없음 |
    | 주의(마이크로슬립) | 1.5초 이상, 3초 미만 | 주의 표시 |
    | 졸음(수면) | 3초 이상 | 경고음·화면 경고 |

    - 판정 불가(얼굴 미검출)와 고개 숙임은 직전까지 이어 감은 시간이 0.5초 이상이면 감은 것으로 이어서 센다(기획서 5-1).
    - 판정 불가가 3초 이어지면 확인 필요 경고를 낸다.
3. **학습 모델**: 3초 창(15 FPS, 45 × 11)으로 1D-CNN·LSTM을 학습한다. 출력은 4클래스 softmax(정상, 눈감김, 하품, 고개숙임)이고, 불확실은 클래스가 아니라 제외 표시다. 학습 창은 0.5초 간격, 실시간 판정은 0.2초 간격이다.
4. **별도 알림**: 하품이 5분에 3회면 하품 주의(알림 후 2분 쿨다운). 고개 숙임은 표시만 한다.
5. Streamlit 화면에 단계와 연속 눈 감김 시간을 실시간으로 보여 주고, 끝나면 주의·졸음·하품 이벤트를 시간순으로 요약한다.

- **공개용 데모 영상은 NITYMED나 자체 촬영 영상으로만 만든다**(DMD는 가공본 배포 금지).

## ▶️ 실행

레포 루트에서 `python -m`으로 실행한다.

```bash
conda activate geumjjogi-drowsy

# 1. 특징 추출 (CPU) → data/features/*.parquet
python -m auto_label.extract

# 2. 사람 검수: NITYMED 고개 숙임 표시 → data/head_down/  (127.0.0.1 로컬 화면)
python -m auto_label.head_review.server

# 3. 라벨 JSON·운전자 단위 분할 → data/labels/, data/split.csv
python -m dataset.convert_labels --with-dmd

# 4. 3초 창·정규화 값 (v7: NITYMED + DMD, 세션 기준 정규화) → data/windows_session/
python -m sequence_model.frames --sources nitymed dmd --relative --out data/windows_session
python -m sequence_model.frames --export data/windows_session   # 기획서 이름 split.json·norm.npz

# 5. 1D-CNN·LSTM 학습 (GPU, 시드 3개) → runs/<tag>/
python -m sequence_model.train --tag v7 --windows data/windows_session

# 6. 평가: Val 선택 → 후처리 선택 → 최종 선택 → 비교표 (--with-webcam: Val2 웹캠 녹화 포함)
python -m eval.evaluate val --tag v7 --with-webcam
python -m eval.evaluate post --tag v7 --with-webcam
python -m eval.evaluate final --tags v6 v7
python -m eval.report                       # 규칙 대 학습 비교표 → runs/compare.md

# 7. 웹캠 녹화 영상 채점 (사람 정답 표시 후)
python -m auto_label.user_review.server --set webcam
python -m eval.score_user --set webcam --tags v8

# 8. 데모 (기본 가중치는 runs/final.json = v8, 11.05 기술서 기준)
python -m demo.webcam --camera 0                        # OpenCV 실시간 (영상 저장 안 함)
python -m demo.webcam --weights runs/v8/cnn1d_v01.pt --record webcam                              # 판정 화면을 보며 녹화(Val2)
#   설정 B(--grace 0.2 --head-rel 10)는 기술서 3.1과 달라 채택하지 않음(11.05). 상대 pitch를 끄면 --head-rel은 효과가 없다
#   --backend DSHOW: MSMF로 카메라가 안 열리거나 느릴 때
python -m demo.demo_video --input <영상> --weights runs/v8/cnn1d_v01.pt   # 판정 화면을 입힌 데모 영상
python -m streamlit run demo/streamlit_app.py           # Streamlit 데모 (http://127.0.0.1:8501). 운전하기(웹캠 계기판·운전 후 리포트), 지난 운전(runs/sessions/ 로그 다시 보기)

# 테스트
python -m unittest discover -t . -s tests
```

### v7·v8 비교와 고개 숙임 상대 pitch 선택 기준 (11.04, 육주영, 결과를 보기 전에 적음)

- 데이터: NITYMED Val 6개 + Val2 웹캠 녹화(사람 라벨, 11.03 2개 + 11.04 1개, 사람 1명). 전부 불확실인 녹화는 채점되지 않는다. Val2가 작아 예비 결과다. Test2는 쓰지 않는다.
  - 이후 Val2 구성(덧붙임): 11.04 저녁 5개(11.03 2개 + 11.04 집 3개), 11.05 9개(+ 11.04 학원 2개·11.05 2개). 11.04 학원 181129는 시작 60초에 얼굴이 없어 제외했고(실험 기록 11.05), 11.04 집 200549는 전부 불확실이라 채점되지 않는다.
- 비교 대상: v7, v8(각자 `post.json`), v8의 고개 숙임 기준 후보(절대 25도, 정면 기준 상대 10·12.5·15·17.5도).
- 주 지표: 3초 재현율. 같으면 3초 시간당 오경보, 그다음 3초 지연이 작은 쪽.
- 조건: 3초 시간당 오경보가 기준(v8 절대 25도)의 1.5배 이하. 고개 숙임 후보는 NITYMED Val 고개 숙임 구간 F1이 절대 25도보다 낮지 않아야 한다.
  - 11.05 철회: 기획서 7-3·기술서 7장에서 오경보율은 "값 보고"라 한도를 두지 않는다. 경고를 남발하는 모델은 문서 지표인 눈 감김 구간 F1(규칙 대비 향상)에서 걸러진다. 원문은 기록으로 남긴다.
- 보조로 보고만 한다: 주의(1.5초) 재현율·오경보, 눈 감김 구간 F1.
- 결과(11.04 녹화 추가 후). Val2는 녹화 5개, 10.7분, 3초 이상 눈 감김 29개다. 4개였을 때는 상대 10도가 선택됐는데, 5개로 다시 고르면 17.5도가 선택된다(아래).
- 고개 숙임 기준 후보(v8, grace 0):

  | 기준 | Val2 3초 재현율 | Val2 3초 오경보/시간 (한도 35.5) | Val 3초 오경보 (한도 12) | Val 고개숙임 F1 |

- v7·v8(상대 17.5, grace 0): v7은 3초 재현율 0.816, 오경보 27.6/시간, 눈 감김 구간 F1 0.765이고, v8은 0.736·23.7·0.597이다. 규칙 EAR 0.48은 0.483·11.8이다. v8은 웹캠에서 눈 감김 구간 F1이 v7보다 계속 낮다. v8 학습 데이터는 NITYMED뿐이고, v7은 DMD를 더했으며 세션 기준 정규화를 썼다.
- 짧은 끊김 허용(grace)은 눈 감김 타이머라 김민영 님 담당이다. 값은 바꾸지 않고 수치만 공유한다. Val2 3초 재현율 / 오경보:

### 기획서·기술서와 다른 점 (갱신 안건, 11.05 정리)

기준 문서는 기획서 v1·기술서 v3(둘 다 11.04판, `docs/plan.md`·`docs/spec.md`)이다. 11.05 사용자 결정: 모두 기획서·기술서 내용으로 맞춘다. 문서에 없는 방법을 다시 쓰려면 팀 합의 후 문서를 먼저 고친다(`docs/` 브랜치 PR).

1. 오경보 한도(기준 × 1.5, `eval/evaluate.py` `ALARM_FACTOR`, "수정 기획서 F"): **철회.** 문서대로 값만 보고한다. 코드(`tune_post`·`final`)는 남아 있지만 결정에 쓰지 않는다.
2. 최소 눈 감김 0.1초·켜짐 0.6·꺼짐 0.4: **반영.** v8 `post.json` `min_close` 0.0 → 0.1(켜짐·꺼짐은 이미 같음). 타이머(`ClosureTimer`)는 grace 0이면 0.1초 미만 감김이 1.5초에 닿지 못하므로 단계 결과가 같다.
3. grace: **기술서 3.1대로 0**(눈을 뜨면 처음부터). 설정 B는 채택하지 않는다. `--grace` 옵션 코드는 남겨 둔다(김민영 님 담당).
4. 세션 기준 정규화·상대 pitch: **기술서대로 쓰지 않는다.** v7을 후보에서 빼고 `runs/final.json`을 v8로 바꿨다(이전 파일 `runs/final_v7_1104.json`). `config.HEAD_PITCH_RELATIVE = False`(절대 `HEAD_PITCH_DOWN` 25도). v7을 쓰지 않으므로 시작 60초 무검출 IndexError도 기본 경로에서는 나지 않는다.
5. DMD 평가(기술서 7장: NITYMED 검수 + DMD 변환 라벨, A·B 기준, 출처별): **대기.** 레포 어느 브랜치에도 기술서 5.6의 `dmd_convert.py`·`best_params.json`이 없고, 로컬 `data/labels`의 DMD 라벨 15개는 규칙이 기술서 5.4와 다르다("close 중 0.5초 이상만, closing은 뜸", `label_status` `reviewed`). 장범수 님께 `dmd_convert` 결과(A·B 기준)를 받아야 한다. v8은 DMD로 학습하지 않았으므로 받으면 DMD로 평가할 수 있다(보정에 쓴 운전자는 뺀다).

### 팀 코드와 다른 점 (PR에서 정할 것)

11.04에 팀원 파일(`landmarks/`, `rule_based/alarm.py`·`config.py`·`eyes.py`, `sequence_model/build_windows.py`)을 main 버전으로 되돌렸다. 남은 차이는 아래와 같다.

- **눈 감김 타이머:** 데모·평가는 `rule_based/closure_timer.py`의 `ClosureTimer`(이어받기 0.5초, 하품 중에도 계속 셈, 기술서 3.1~3.3)를 쓴다. 김민영 님 `rule_based/alarm.py`에 합칠지 PR에서 정한다.
- **창 함수:** v1~v7 창과 실시간 판정은 `sequence_model/frames.py`를 쓴다. v8부터의 팀 공통 창 묶음은 `sequence_model/build_windows.py`(김민영)가 만든다.
- v7까지의 가중치와 기존 `data/features`는 이전 좌우 순서(`LEFT_EYE = (33, …)`)로 만들었다.
- **고개 숙임 기준:** 데모·평가(육주영)는 정면 기준 상대 pitch 17.5도(`config.HEAD_PITCH_DOWN_REL`)를 쓴다. 김민영 님 `rule_based/config.PITCH_DOWN`(절대 15도)과 다르다. PR에서 정한다.
